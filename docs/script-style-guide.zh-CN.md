# 视频稿件完整写作规范

> 版本：1.0
> 适用范围：科普、科技、体育、电影、历史、自然奇观和旅游 Vlog。
> 使用对象：选题策划、资料研究者、写稿 Agent、人工审稿人和剪辑师。
> 核心原则：先确认事实和可用素材，再写能被朗读、能被剪辑、能被追溯的稿件。

## 1. 规范目标

一份合格稿件必须同时满足五个条件：

1. **可朗读**：中文自然，术语可读，句子适合老师口播。
2. **可核验**：事实、数字、日期、人物关系和引用均能追溯到来源。
3. **可剪辑**：每个重要画面都能找到素材 ID、文件、时间码或网络来源。
4. **可复核**：不确定内容不会混入净稿，而是进入人工确认队列。
5. **可交付**：稿件、素材索引、事实来源和待补素材使用统一格式。

本规范不要求 Agent 假装完整理解数小时原片。长视频应先经过素材扫描、代理帧、转写、语义分段和人工复核，再进入写稿阶段。

## 2. 两种任务模式

### 2.1 `TOPIC_FIRST`：从空泛题材开始

适用于“介绍水星”“介绍某个自然奇观”等没有本地素材的任务。

顺序：

1. 明确受众、目标时长和主题边界。
2. 建立事实问题清单。
3. 查找权威资料并登记来源。
4. 建立所需画面清单和许可状态。
5. 根据可获得的素材安排结构。
6. 写带素材锚点的稿件。

不得先写完整旁白，再临时寻找无法匹配的画面。

### 2.2 `FOOTAGE_FIRST`：从已录制素材开始

适用于乐高乐园、中途岛号博物馆等先拍摄、后写稿的项目。

顺序：

1. 读取素材清单、接触表、转写和语义索引。
2. 按内容而不是固定时长合并片段。
3. 区分画面价值和音频价值。
4. 确认现有素材能支撑哪些章节。
5. 列出缺少的网络素材和事实资料。
6. 先做人工高风险确认，再写最终稿。

不得仅凭文件名、单张抽帧或自动转写判断完整内容。

## 3. 写稿前必须提供的项目配置

每个项目应有一份配置；缺少的字段必须显式标为 `UNKNOWN`，不得猜测。

| 字段 | 含义 |
|---|---|
| `project_id` | 项目唯一标识 |
| `task_mode` | `TOPIC_FIRST` 或 `FOOTAGE_FIRST` |
| `topic` | 本期主题 |
| `content_domain` | 科技／体育／电影／历史／自然／旅游等 |
| `audience` | 目标观众及其知识水平 |
| `target_duration` | 预计成片时长 |
| `speech_rate_profile` | 已校准的朗读者语速配置；没有则标记待测试 |
| `part_id` | 当前 Part；整片任务可使用 `FULL` |
| `previous_part_summary` | 上一 Part 的结尾和未完句 |
| `next_part_plan` | 下一 Part 的开头或衔接目标 |
| `target_local_footage_ratio` | 本地素材占比目标；按项目设置，不全局写死 |
| `required_sections` | 必须覆盖的章节 |
| `excluded_topics` | 本期明确不写的内容 |
| `approval_constraints` | 审核和发布限制 |
| `available_inputs` | 清单、转写、接触表、来源资料等路径 |

朗读速度沿用已经由用户确认的项目配置。只有更换朗读者、改变语言风格或大幅改稿时，才重新做一分钟语速测试。

## 4. 信息来源与可信度

### 4.1 来源优先级

从高到低使用：

1. 用户明确确认的项目事实和范围。
2. 本地原始视频、原始照片和人工回听的原声。
3. 官方机构、博物馆、公司、赛事组织、论文或政府资料。
4. 可靠的权威二手资料。
5. 自动转写、视觉识别和旧稿中的待核验内容。

旧稿可以作为结构和语气参考，但不能自动成为事实来源。自动转写可以帮助定位，却不能直接证明专业词、专名和数字正确。

### 4.2 事实状态

所有知识性陈述必须属于以下状态之一：

| 状态 | 允许进入带标注稿 | 允许进入净稿 |
|---|---:|---:|
| `VERIFIED` | 是 | 是 |
| `LOCAL_CONFIRMED` | 是 | 是；仅限原片明确支持的观察或原声 |
| `CONFLICT` | 是，必须说明冲突 | 否 |
| `HUMAN_REVIEW` | 是，作为问题 | 否 |
| `UNVERIFIED` | 是，作为缺口 | 否 |
| `OMIT` | 仅记录省略原因 | 否 |

禁止用“可能”“据说”“有人认为”等模糊措辞把未核验内容伪装成可发布事实。

### 4.3 必须逐项核验的内容

- 精确年份、日期、数量、比例、价格、距离、高度和排名。
- 人名、地名、舰名、机型、建筑名和组织名。
- “第一”“最大”“唯一”“最早”等极值表述。
- 人物观看某场比赛或某部作品的地点、时间和因果关系。
- 引语、因果关系、动机和心理活动。
- 网络图片、视频和音乐的许可与署名要求。

## 5. 叙事风格

### 5.1 总体语气

- 正面、热情、清楚，允许轻微幽默。
- 用具体画面、动作和对比推动叙事，不堆百科条目。
- 不通过灾难、丑闻、政治冲突或未经证实的负面故事制造刺激。
- 审核要求不能成为歪曲事实的理由；如果必要事实与限制冲突，应提交人工决定或缩小选题。
- 不把广告式夸赞写成事实，不连续使用“震撼”“传奇”“令人惊叹”等空泛形容词。

### 5.2 推荐结构

每个 Part 通常包含：

1. **钩子**：强画面、反差、问题或重复句式。
2. **定位**：说明地点、对象和本段要回答的问题。
3. **推进**：按时间、空间、城市、人物行动或因果顺序展开。
4. **尺度转换**：把大数字换成熟悉的物体、时间或可见细节。
5. **人物或概念揭晓**：有证据时，可以先铺经历和影响，最后报出名字。
6. **收束与转场**：回答开头问题，并自然连接下一 Part。

一个 Part 不必机械包含全部技巧。钩子和转场必须服务于真实内容。

### 5.3 “先铺信息，后揭晓”

可以先描述人物的年龄、经历、成就或当时处境，最后揭晓姓名。但必须满足：

- 所有铺垫事实均有来源。
- 观看行为、地点和因果关系有直接证据。
- 只能证明年龄时，只写年龄，不能补写“他正在电视机前观看”。
- 不允许为了故事完整而虚构母亲、少年、观众或命运转折。

### 5.4 时间节点与跨领域呼应

当稿件出现明确年份或日期时：

1. 先解释该时间点与当前主题直接相关的事件。
2. 如果联系自然，可以补充一件同期、正面且可核验的科技、体育或电影事件。
3. 跨领域事件只能帮助观众建立时代感，不能喧宾夺主。
4. 找不到自然联系时不强行添加。

科技题材可以借体育或电影建立时代坐标；体育题材也可以借科技或电影。所有联系都必须有来源，不能只靠年份相同。

## 6. 口播语言

### 6.1 句子和段落

- 使用自然中文口语，但保持知识类视频的准确度。
- 每句话只承担一个主要信息任务。
- 长定语、多个数字和连续英文术语应拆句。
- 段落开头先给主题，段落结尾提供递进或转场。
- 避免连续三句使用相同句式，除非有意使用排比。
- 不使用只有写作者看得懂的缩写、代词或悬空指代。

字数与时长必须根据 `speech_rate_profile` 计算。没有语速配置时，只能给出待校准估算，不能声称精确时长。

### 6.2 中文与英文术语

新出现或不为大众熟悉的术语，第一次出现时写为：

`中文名称（English Name）`

要求：

- 英文主要帮助老师发音和断句，不强制上屏。
- 人名采用权威来源中的拼写。
- 同一 Part 内已经解释过的术语不重复加英文。
- 跨 Part 是否重复，由项目术语表和观众记忆负担决定。
- 不允许连续堆叠多个未解释的英文术语。
- 自动转写中的专业词必须回听或查证后才能使用。

### 6.3 数字

- 数字第一次出现时说明单位和对象。
- 连续多个数字要分组，不在一句里塞入过多指标。
- 尽量增加尺度转换，但转换本身也必须可计算、可复核。
- 近似值明确写“约”；来源给出精确值时不得随意改成更戏剧化的数字。

## 7. 画面与稿件同步

### 7.1 素材类型与 ID

统一格式：`{PART}-{TYPE}-{NN}`。

| 类型 | 含义 | 示例 |
|---|---|---|
| `VID` | 本地视频 | `13A-VID-01` |
| `IMG` | 本地图片 | `13A-IMG-01` |
| `WEB` | 网络图片或视频 | `13A-WEB-01` |
| `GFX` | 头像、数据卡、进度条等图层 | `13A-GFX-01` |

规则：

- 一个 ID 只对应一个实际素材。
- 现实照片、模型照片、地图和视频不能共用一个 ID。
- 同一素材重复使用时沿用原 ID，正文重新写一组起止锚点。
- 素材替换但叙事功能不变时可以保留 ID，同时更新索引并记录变更。
- 不允许出现只有 `[part1]`、没有文件和时间码映射的孤立标签。

### 7.2 正文标注语法

本地视频：

```text
[13A-VID-01+ | 源 00:04–00:18 | AMBIENT_LOW | 城市广角]
旁白……
[13A-VID-01-]
```

本地图片：

```text
[13A-IMG-01 | 4s | 缓慢推近 | 地标定场]
```

网络素材：

```text
[13A-WEB-01 | 5s | HUMAN_REVIEW | 现实照片与模型对照]
```

后期图层：

```text
[13A-GFX-01 | 7s | 长方形头像＋数据卡 | 不遮挡字幕]
```

事实引用放在对应句末：

```text
这一更新区域使用超过一百五十万块积木。[F-13A-01]
```

`源时间`始终表示原文件时间码，不是成片时间码。结构预算和预计成片位置必须另列，不能混用。

### 7.3 画面密度

默认目标来自现有制作习惯，可由项目配置覆盖：

- 历史或资料密集段：每句话约 1–2 张图；单张静态图尽量不覆盖超过约 20 个汉字的旁白。
- 旅游和地标段：新地名、地标或术语尽量立刻出现对应画面；单张静态图尽量不覆盖超过约 10 个汉字的旁白。
- 优先使用有信息量的视频，不用静态图片填满整个长段落。
- 竖屏素材可以复制或设计背景填充，但不得把内容无关的三个竖屏强行并排。

这些是剪辑密度目标，不是删改事实或制造无关素材的理由。

### 7.4 网上素材

- 搜索结果页面、缩略图和 Google Maps 搜索截图不作为默认成片素材。
- 优先使用自有素材、官方可转载素材、CC0、Public Domain Mark 或允许相应用途的 CC BY 素材。
- 索引必须保存来源页、作者、许可名称、许可链接、最终文件名和署名文本。
- 官方新闻稿可以是事实来源，但不自动等于图片可转载。
- 没有合格候选时标记 `OMIT` 或调整剪辑，不用错误图片填空。

## 8. 本地视频的音频策略

画面价值和音频价值必须分别判断。

| 状态 | 使用条件 | 稿件要求 |
|---|---|---|
| `ORIGINAL_GUIDE` | 讲解清楚且与主题相关 | 提供中文大意；专业词和数字回听核验 |
| `AMBIENT_LOW` | 走道、甲板、城市环境等需要现场感的 B-roll | 中文旁白为主，原声降低为背景 |
| `MUTE_VO` | 原声过长、偏题、难听清或需要统一中文叙述 | 只能概括材料支持的信息 |
| `MUTE_DELETE` | 片段不进入时间线 | 不为废片强写旁白 |

补充规则：

- 画外英文讲解可以保留，但连续使用通常控制在约一分钟以内；超过时拆段、配字幕或改中文概述。
- 狭窄舷梯、重复爬梯、长期人物遮挡、无信息闲聊和严重损坏素材默认不进入主线。
- 外部走道、港区、飞行甲板等可以保留较低环境声。
- 跨文件未讲完的句子必须标记 `KEEP_CONTINUITY`，与下一文件一起处理。

## 9. 人工复核

### 9.1 必须提交人工的问题

- 低置信度地标、人物、设备或术语识别。
- 原声中听不清的专名、数字和关键句。
- 来源冲突或缺少权威来源的事实。
- 网络素材许可不清楚。
- 是否保留人物照片、闲聊或较长画外原声。
- 片段跨文件连续、最终切点和内容取舍。
- 审核限制可能导致内容失真的情况。

### 9.2 问题格式

每个问题只询问一个决定，并附最少必要证据：

```text
H-13A-01
位置：13A-VID-03 00:12
候选：奥库路斯交通枢纽（Oculus Transportation Hub）
依据：外形与权威来源图片相符，但当前只有代理帧。
问题：是否确认在净稿中使用该名称？
默认处理：未确认则写“白色翼状建筑”，不写专名。
```

不得把低置信度判断直接写入净稿后，再笼统要求“请人工检查全文”。

## 10. 包装与导出相关规则

这些规则属于项目级交付检查，不应干扰事实和叙事主线。

### 10.1 头像覆盖，低优先级

每连续三个 Part 为一组，可安排：

- 1 处长方形头像，持续 3–10 秒。
- 3 处圆形头像，每处持续 3–10 秒。

不要求每个 Part 各放一套。只有在不遮挡地标、字幕、人物眼睛和关键动作时才使用。跟踪效果不自然时取消。

### 10.2 进度条

- 字号 18。
- Y 轴 20。
- 字重 Medium。
- 字体颜色黑色。
- 全片保持一致。

### 10.3 片尾与导出包

交付前检查：

- 两张推荐视频封面来自最近的相关题材，且文件没有 Offline。
- 封面与链接指向同一视频。
- 人员表包含所有真实参与者及其正确分工。
- 成片小于 8 GB，并提供独立音频。
- 提供 16:9（小于 2 MB）、4:3 和 3000×3000 封面。
- 提供标题、以 `#` 分隔的关键词和时间轴。

## 11. 标准交付文件

每个 Part 至少输出：

```text
{project_id}_{part_id}_script_annotated.md
{project_id}_{part_id}_script_clean.md
{project_id}_{part_id}_editing_index.csv
{project_id}_{part_id}_fact_sources.csv
{project_id}_{part_id}_review_queue.md
{project_id}_{part_id}_run_manifest.json
```

用途：

- `script_annotated.md`：旁白、素材锚点、事实编号和剪辑说明。
- `script_clean.md`：老师录制用净稿，只保留可朗读文字和必要英文。
- `editing_index.csv`：素材 ID 到文件、时间码、用途和音频状态的映射。
- `fact_sources.csv`：事实编号、陈述、来源和核验状态。
- `review_queue.md`：仍需人工决定的问题。
- `run_manifest.json`：输入文件、配置、生成时间、版本和完成状态。

## 12. 净稿规则

净稿中只允许：

- 已核验并可发布的中文旁白。
- 帮助发音和断句的必要英文括注。
- 用户明确要求保留的朗读提示。

净稿中禁止：

- 素材 ID、时间码、事实编号和网址。
- `HUMAN_REVIEW`、`UNVERIFIED` 或占位文字。
- 剪辑动作、许可提醒和内部置信度。
- 自动转写原文中的未复核专业词。
- 模型自述、道歉、推理过程和“作为 AI”等措辞。

只要关键事实仍处于 `CONFLICT`、`HUMAN_REVIEW` 或 `UNVERIFIED`，交付状态就不能标为 `READY_TO_RECORD`。
此时不得输出任何看似可录制的旁白；`script_clean.md` 只保留 `NOT_READY_TO_RECORD` 状态和处理指引。

## 13. 发布前检查表

### 13.1 内容

- [ ] 开头明确本 Part 的问题或看点。
- [ ] 结构按时间、空间或因果推进，没有资料堆砌。
- [ ] 每个明确年份都解释了主题相关事件。
- [ ] 跨领域呼应自然、正面、可核验。
- [ ] 人物揭晓没有虚构观看行为或因果关系。
- [ ] 结尾回答开头并连接下一 Part。

### 13.2 语言

- [ ] 新术语首次出现时附正确英文。
- [ ] 专名、数字、单位和极值表述已核验。
- [ ] 句子适合口播，没有连续堆叠术语和数字。
- [ ] 时长依据已校准语速计算，或明确标记待测试。

### 13.3 素材

- [ ] 每个正文素材 ID 都能在索引中找到。
- [ ] 视频使用原文件时间码，不把结构预算当源时间码。
- [ ] 音频模式只能使用四个标准值。
- [ ] 网络素材记录了来源、作者、许可和署名。
- [ ] 没有用错误图片或缩略图填补缺口。

### 13.4 复核与净稿

- [ ] 所有低置信度判断进入独立问题队列。
- [ ] 净稿不含未核验陈述、占位符或内部标签。
- [ ] 跨文件未完句已检查连续性。
- [ ] 人工参与者和修改记录可追溯。

## 14. 质量红线

出现以下任一情况，稿件必须退回：

- 虚构人物行为、地点、引语、动机或因果关系。
- 把自动转写或视觉猜测直接写成确定事实。
- 事实句没有来源，或来源与陈述不匹配。
- 素材 ID 无法在索引中定位。
- 网络素材没有来源页或许可状态。
- 为满足正面语气而隐瞒或扭曲关键事实。
- 声称 AI 已完整看完原片，但实际只使用抽帧或摘要。
- 净稿仍包含待确认内容。

本规范的目标不是让 Agent 独立完成所有创作，而是让自动化结果可验证、可修改、可执行。
