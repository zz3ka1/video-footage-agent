# 长视频素材到稿件的Agent工作流

## 1. 项目扫描

先生成完整素材清单和三帧总览，回答以下问题：

- 文件是否缺号、重复或损坏？
- 总时长和总大小是多少？
- 主要场景和拍摄日期如何分布？
- 哪些文件值得完整分析，哪些明显只是转场？

这一步只建立项目地图，不写最终旁白。

## 2. 技术粗筛

对高价值或较长文件按低分辨率代理帧扫描：

- 黑屏、严重过暗或过曝。
- 清晰度明显低于同一素材的其他部分。
- 几乎静止或视觉变化异常大的窗口。
- 带时间码的接触表。

`large_visual_change`可能只是正常走动、转身或穿过舱门，因此只能标为`REVIEW`，不能自动删除。

## 3. 音频与画面分开理解

长手持镜头常出现“画面普通、讲解重要”或“画面漂亮、闲聊无关”两种情况。建议分别建立：

- 画面价值：`KEEP / SALVAGE / REVIEW / LOW_VALUE / TECHNICAL_FAIL`。
- 音频处理：`ORIGINAL_GUIDE / AMBIENT_LOW / MUTE_VO / MUTE_DELETE`。

只有合并这两类判断，才能生成可靠的剪辑指示。

## 4. 语义索引

AI或人类根据接触表、转写和必要的原片回看，把固定时间窗口合并成语义段落。每段至少包含：

- 统一素材ID。
- 来源文件和原始时间码。
- 画面内容。
- 原声内容和中文大意。
- 音频模式。
- 建议使用方式和替换画面需求。
- 置信度与人工复核状态。

不要把自动转写直接当成最终稿。专业词、专名、数字和日期必须回听或查证。

## 5. 先建立素材缺口，再写稿

每个章节先列出已有画面和缺少的画面，例如：

- 已有现场控制台，但缺少设备原理示意。
- 有画外讲解，但讲解员被遮挡，需要补充B-roll。
- 旁白涉及历史日期，需要官方照片和事实来源。

在素材可获得性明确后写稿，可以避免完成旁白后才发现没有可用画面。

## 6. 人工确认点

建议人类只处理高价值决策：

- `KEEP`与`SALVAGE`是否符合真实剪辑标准。
- 画外原声能连续使用多久。
- 哪些现场闲聊需要保留人物感。
- 哪些事实或素材授权仍未核验。
- 最终剪切点、字幕和音乐处理。

目标不是消除人类，而是把“完整重看数小时原片”压缩成“复核一份结构化候选清单”。
